版本：v2.0

# 1. 当前版本总体架构分析

当前版本采用：

```
键盘输入
    |
    v
dispatch()
    |
    v
inputXXX() / handlePowerOperation() / doDel()
    |
    v
AST Expression Tree
    |
    v
render()
    |
    v
LCD显示
```

表达式数据结构：

```
root
 |
 +-- token
 |
 +-- token
 |
 +-- pow
      |
      +-- base[]
      |
      +-- exp[]
```

例如：

```
2^3^4
```

内部表示：

```
pow
├── base:[2]
└── exp:[
        pow
        ├── base:[3]
        └── exp:[4]
    ]
```

当前设计优势：

1. 表达式不是字符串，而是结构化树。
2. 光标不是DOM位置，而是逻辑位置。
3. 可以支持自然显示格式。
4. 可以支持嵌套指数。


当前代码中：

```
stack=[
 {
   arr:root,
   pos:0
 },
 {
   arr:pow.exp,
   pos:2,
   node:pow,
   slot:"exp"
 }
]
```

表示光标所在层级。

# 3. 当前主要问题分析


# 问题1：指数导航依赖大量特殊判断，扩展性不足


当前：

```
getPowerContext()

        |
        |
        +-- OUTSIDE_POWER

        +-- EXP_END

        +-- BASE_EXP_BOUNDARY

        +-- NUMBER_MIDDLE
```

然后：

```
handlePowerOperation()

        |
        +-- opExpEnd()

        +-- opBaseExpBoundary()

        +-- opNumberMiddle()
```

目前逻辑可以覆盖：

```
2^3
2^3^4
123|456 ^()
```

等情况。


但是问题：

指数规则被写死在：

- 输入
- 左右移动
- 删除

三个模块中。

例如：

LEFT：

```
doLeft()
```

需要知道：

```
pow
 |
 base
 |
 exp
```

特殊情况。

RIGHT：

```
doRight()
```

也需要重新判断。

DEL：

```
doDel()
```

再次实现一套指数规则。

结果：

三个模块分别维护指数行为。


风险：

以后增加：

```
x^(y^z)

(x^2)^3

2^(3+4)

2^(-3)
```

容易出现：

输入正确

但是：

LEFT错误

或者：

DEL错误。

# 问题2：pow的光标位置模型不统一


当前：

```
digitsIn(pow)
=
base长度
+
^符号
+
exp长度
```

但是：

嵌套指数：

```
2^3^4
```

又特殊处理：

如果：

```
exp开始位置也是pow
```

则取消^

代码：

```javascript
if(powExpStartsWithPower(n))
```

修改了长度规则。


这导致：

同一个表达式：

不同层级：

使用不同offset。


问题：

光标实际上不知道：

当前位置代表：

```
base结束

还是

指数开始
```


建议：

取消：

```
^字符位置
```

作为光标位置。


改为：

结构位置。

# 4. 新版设计方案


核心思想：

## 光标从“数字位置”升级为“树位置”


新的Cursor：

```javascript
Cursor
{
    node,
    slot,
    offset
}
```


例如：

2^3^4


光标：

```
2 | ^ 3 ^ 4
```


表示：

```
Cursor
{
 node:pow,
 slot:"base",
 offset:1
}
```


而不是：

```
arr=root
pos=3
```

# 6. Cursor系统重构


## 新Cursor结构


```javascript
class Cursor{


constructor(){

    this.path=[];

}


current(){

    return this.path[
        this.path.length-1
    ];

}


}

```


路径：

```
root

 |
 pow

 |
 exp

 |
 inner pow

 |
 base
```


例如：

```

```

```
root
 |
```

# 13. 总结


当前版本：

优点：

- AST设计正确。
- 指数节点设计正确。
- 已解决大量显示问题。
- stack光标思想方向正确。


主要缺陷：

不是指数算法错误，而是：

```
Cursor模型
+
Power规则
+
Delete规则
```

三者耦合。


下一版本核心修改：

从：

```
offset驱动编辑
```

升级为：

```
AST路径驱动编辑
```


这样可以稳定支持：

```
2^3^4^5

(a^b)^c

2^(3+4)

2^(-x)

```


并且以后增加：

```
积分
求和
矩阵
函数嵌套
```

不会继续增加特殊判断。
