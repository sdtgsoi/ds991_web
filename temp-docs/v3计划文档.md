主要问题：

## 2.1 输入和数学耦合

例如：

按：

```

```

当前：

```
dispatch

↓

判断cursor

↓

创建pow

↓

输入模块知道AST结构。

问题：

```

---

## 2.2 Cursor和AST耦合

当前：

```javascript
{

 pos
}
```

问题：

光标依赖数组位置。

但是数学结构：

```
pow

fraction

root
```

都是树。

数组offset无法表达：

```
当前位置属于哪个数学槽
```

---

## 2.3 删除逻辑复杂

当前：

DEL需要知道：

```

节点删除

分数删除

```

导致：

```

```

越来越大。

# 7. AST设计

## Node基类

```javascript
class Node{


constructor(type){

this.type=type;

}


evaluate(context){}


render(context){}


clone(){}


}

```

---

# NumberNode

```javascript
class NumberNode extends Node{


constructor(value){

super("number");

this.value=value;

}


evaluate(){

return Number(this.value);

}


}

```

---

# PowerNode

```javascript
class PowerNode extends Node{


constructor(){

super("power");

this.base=[];

this.exp=[];

}


evaluate(ctx){

let b=evaluate(this.base);

let e=evaluate(this.exp);

return Math.pow(b,e);

}


}

```

# 20. 最终目标

最终：

```
Calculator


        Input

          |

       Command

          |

        Editor

          |

         AST

          |

     +------+------+

     |             |

 Renderer     Evaluator


```

最终代码规模：

```
当前:

1个HTML
约数万行


v3:

约100个模块

每个100~300行

```

优势：

* 新增数学结构不会污染已有代码；
* 指数、分数、积分统一；
* 光标规则集中；
* 删除逻辑可测试；
* 可以继续实现完整fx-991功能；
* 未来支持CAS。

# 结论

当前版本最值得保留：

✅ AST思想
✅ Natural Display思想
✅ Template Slot思想

最需要改变：

❌ dispatch承担全部逻辑
❌ cursor依赖数组offset
❌ delete/input/evaluate/render互相调用

v3核心原则：

> **输入产生命令，命令修改编辑器，编辑器修改AST，Renderer显示AST，Math Engine计算AST。**
