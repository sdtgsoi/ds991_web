# 指数功能需求规格（Power Function Specification）

---

# 1. 指数功能类型

系统支持三种指数输入：

| 按键     | 功能       |
| ------ | -------- |
| `x^()` | 创建可编辑空指数 |
| `x²`   | 创建固定指数 2 |
| `x³`   | 创建固定指数 3 |

三者虽然都会生成 `pow` 结构，但**光标行为和嵌套逻辑不同**，其中`x^2`与`x^3`行为相同。

---

# 2. 指数 AST 结构

指数使用二叉结构：

```
pow
├── base
└── exp
```

例如：

输入：

```
2^4
```

结构：

```
pow
├── base: 2
└── exp: 4
```

---

# 3. x² / x³ / x^() 的区别

## 3.1 x² 和 x³

特点：

* 自动生成指数
* 指数内容固定
* 输入完成后光标不进入指数内部
* 光标返回原编辑层

例如：

输入：

```
2|
```

按：

```
x³
```

结果：

```
2³|
```

AST：

```
pow
├── base:2
└── exp:3
```

cursor：

位于 pow 外部。

---

## 3.2 x^()

特点：

* 创建空指数
* 空指数显示 placeholder 方框
* cursor 进入指数内部

例如：

输入：

```
2|
```

按：

```
x^()
```

显示：

```
   □
2^
```

AST：

```
pow
├── base:2
└── exp:empty
```

cursor：

位于：

```
exp slot
```

---

# 4. 指数上下文判断

指数操作必须根据 cursor 所在 AST 位置判断。

不能通过字符串位置判断。

需要区分：

1. 指数外部右侧
2. 指数内部末尾
3. base 与 exp 之间
4. 数字内部

允许。

生成新的指数嵌套：

原：

├──base:2

唯一规则：

> 除最外层底数之外，所有指数层字号一致。

```

    3

```

禁止：

```

 └3 (70%)
    └4 (49%)
        └5 (34%)
```

# 5.2 指数抬升规则

每一级指数需要正确向右上方排列。

例如：

```
2^(3^4)
```

应该：

```
    4
  3
2
```

不能：

```
   4
 3
2
```

或者：

```
  4
    3
2
```

# 6. 光标显示规则

cursor 必须绑定 AST，而不是字符串位置。

逻辑：

```
cursor path

↓

AST node

↓

layout box

↓

screen position
```

---

不能：

```
字符index × 字符宽度
```

因为：

```
2^(3^4)
```

视觉位置和字符位置不一致。

# 7. 多层指数 viewport 规则

当指数层级增加：

例如：

```
2^(3^(4^(5^6)))
```

整体高度增加。

要求：

* 当前 cursor 永远可见
* 算式位置根据 cursor 实时调整
* 不是固定向下或向上移动

---

例如：

cursor 在顶部：

```
5|
```

整体需要下移。

cursor 回到底数：

```
|2
```

恢复正常。

# 10. DEL 删除规则（指数框）

原则（用户原话）：

> 当光标在当前指数框的开头时直接去掉这一层指数嵌套并将后面内容放到底数的末尾。

即：DEL 在指数框**开头**时，丢弃这一层**方括号**，框内内容不丢失，整体向外移动一层。

| 输入 | DEL 后 |
| --- | --- |
| `123^(⎮456)` | `123456` |
| `123^(⎮)` | `123` |
| `123^(⎮45^67)` | `12345^67` |
| `123^(⎮^45)` | `123^45` |
| `12^(⎮345^67)` | `12345^67` |

其他位置：

* 指数框**内部非开头**：删掉光标左侧一个字符。
* **底数右端**（指数框入口）：指数框为空则去掉整个框，否则删掉指数的最后一个字符。

## 10.1 嵌套时"哪一层"被去掉

`123^(45^67)` 这类形状里，外层指数框里只有一个**幂**。它的**内容**是内层幂的底数（`45`），它的**更高指数**是内层幂的指数（`^67`）。

> 底数吸收内容，更高指数留在外层。

```
12^(|345^67)  ->  12 + 345 挂上 ^67  ->  12345^67
123^(|45^67)  ->  12345^67
123^(|45)     ->  12345
123^(|)       ->  123
123^(|^45)    ->  123^45     （没有内容，只有更高指数）
```

要点：

* 更高指数**不能**挂到"被改写过的数字节点"上（会让数字节点长出 `exp` 属性、结构错乱），必须**新建一个 `pow` 节点**包住最后一个内容记号。
* 光标位置计算见第 11 节。

## 10.2 导航层面的删除规则

* 空指数框**不参与**左右移动（不被停靠），只能经由 `x^()` 进入。
* 从底数右端按 RIGHT 可进入指数框。
* 从指数框开头按 DEL 触发的"拆框"见第 10.1 节。

---

# 11. 删除后的光标落点

原则（用户原话）：

> 整体逻辑是指针要停留在原底数的右侧。

也就是：DEL 拆掉指数框后，光标停在**原来那个底数**的右边，等价于"被删掉的方括号原来的位置"。

| 输入 | DEL 后（⎮ 为光标） |
| --- | --- |
| `123^(⎮45)` | `123⎮45` |
| `123^(⎮456)` | `123⎮456` |
| `123^(⎮^45)` | `123⎮^45` |
| `123^(⎮)` | `123⎮` |
| `123^(⎮45^67)` | `123⎮45^67` |
| `12^(⎮345^67)` | `12⎮345^67` |

注意：**不是**停在合并后整段的末尾。

* `123^(⎮45^67)` 是 `123⎮45^67`，**不是** `12345⎮^67`。
* `12^(⎮345^67)` 是 `12⎮345^67`。

## 11.1 实现要点

1. 合并时把底数**拆成单字符令牌**（`"123"` → `1`,`2`,`3`）。否则光标在 `"12345"` 这个数字**内部**没有落脚点，只能停在末尾。
2. 渲染器需要能在幂的"底数之后"那个偏移断开标记：幂的位宽是 `[底数][^][指数]`，"底数之后"正好是 `^` 本身。
   * 用 `arrDigits` 而**不是** `slotDigits` 判断该偏移（后者有最小值 1，会算错；曾因此把 `5²` 画成 `52`）。

# 12. 指数框内的左右导航

## 12.1 空指数框

空指数框没有内容可走，按 LEFT 直接**离开该幂**，落到幂外左侧；不参与常规左右移动。

```
2^( )   起点 2^(⎮)      LEFT -> ⎮2^( )
```

## 12.2 有内容的指数框

* 指数框**内部最左**按 LEFT：落到**底数右端**（视觉上紧贴指数框左边）。
* **底数**按 LEFT：应**离开整个幂**（而不是回到刚刚离开的指数框）。这条曾出过 bug：`2^(3^4)` 需要多按一次才过得去。

## 12.3 层边界只有一个位置（重要模型）

> 内层 base 的第 0 位和外层指数的第 0 位**是同一个位置**，不应出现两个状态。

即 `1^(2^3)`：

```
外层幂
├── base: 1
└── exp: 内层幂
          ├── base: 2
          └── exp: 3
```

编辑第二层只对应**第二个 base**，所以不应存在"内层 base 第 0 位"与"外层 exp 第 0 位"两个位置。

设计模型（用户确认）：

> **底数层没有单独的框需要跳出。**

| 状态 | 含义 |
| --- | --- |
| 未见 `^` | 底数就是普通内容，按普通记号移动 |
| 已见 `^` | 出现指数框，光标进入框内；底数留在框外，不再是需要"跳出"的层 |

由此，`2^(3^4)` 只应有这些位置：

```
2⎮{3^{4}}      ← 外层底数右端（= 外层 exp 的入口，同一处）
2^{3⎮{4}}      ← 内层底数右端
2^{3^{4⎮}}     ← 内层 exp 内
2^{3^{⎮4}}     ← 内层 exp 内（最左）
```

**没有** `2^{⎮3^{4}}` 这个独立位置。

# 15. 位置模型与实现说明

## 15.1 单一事实来源

* `ds991.html` 是**唯一**编辑对象，`index.html` 由 `./sync.sh` 生成，禁止手改。
* 改完跑 `./sync.sh`，并用 `./sync.sh --check` 确认两份一致。

## 15.2 位置用"数字偏移"

* 光标位置是**数字偏移**（digit offset），不是记号下标。
* 一个记号占几位由 `digitsIn` 决定；模板内部可停的区域由 `slotKeys` 决定。
* `slotDigits(a) = max(1, arrDigits(a))`；判断"空/非空"必须用 `arrDigits`。

## 15.3 `^` 偏移的重复计数问题

`pow` 现在的位宽：

```js
if(tn==="pow") return slotDigits(n.base) + (powExpStartsWithPower(n) ? 0 : 1) + slotDigits(n.exp);
```

> 当指数字段**以幂开头**时，不为 `^` 单独计一位。

原因：此时 `^` 与内层幂的首位是**同一个显示位置**，再计一次就会让同一处出现两个内部状态，导致每层边界多按一次左键。

配套地，`descendAtCursor` 的 `pow` 分支：

```js
var bd = slotDigits(n.base);
var hasCaret = !powExpStartsWithPower(n);
if (hasCaret ? (off <= bd) : (off < bd)) { slot="base"; rel=Math.min(off, arrDigits(n.base)); }
else { slot="exp"; rel=off - (hasCaret ? bd+1 : bd); }
```

## 15.4 已交付的两处改动

| 位置 | 改动 |
| --- | --- |
| `digitsIn` 的 `pow` 分支 + 新增 `powExpStartsWithPower()` | 指数以幂开头时不计 `^` 偏移 |
| `descendAtCursor` 的 `pow` 分支 | 无 `^` 偏移时 base 块为 `0..bd-1`，边界归 exp |

效果：`2^(3^4)` 的内部位置数从 5 降到 3（位宽与视觉位置数对上）。

# 16. 已知问题（待修）

## 16.1 层边界仍多按一次左键

现状（`⎮` 为光标）：

```
12^(34^56)
  起点    12^{34^{56⎮}}
  LEFT1   12^{34^{5⎮6}}
  LEFT2   12^{34{⎮56}}
  LEFT3   12^{34⎮{56}}
  LEFT4   12^{3⎮4{56}}
  LEFT5   12{⎮34{56}}
  LEFT6   12{⎮34{56}}   ← 重复一次
  LEFT7   12⎮{34{56}}
  LEFT8   1⎮2^{34^{56}}
  LEFT9   ⎮12^{34^{56}}
```

`2^(3^4)`、`2^4` 同样各重复一次；`123^456`、`2^( )` 正常。

**根因（已用仪器定位）**：`doLeft` 在内层 base 处调用 `leaveField(-1)`，而 `leaveField` 把外层位置设成

```
tokenStart + digitsIn(内层幂)
```

这个值**塌缩到外层指数的起点**，于是下一次左键产生重复。

**修法方向**：`leaveField` 不应使用 `digitsIn`，而应统一取"该槽的最后一个真实位置"。但此处该位置属于**外层幂节点内部**的偏移，不同数组之间坐标不同，简单的 `+1` / `arrDigits(base)` 修正都会引入回绕（LEFT6 跳回 LEFT3、LEFT7 跳回起点）并撞坏两条 DEL 合并断言。

## 16.2 建议的修复流程（上一轮教训）

1. **先写逐位置断言**，把当前走位钉死（含"不应重复"的期望）。
2. 再改 `leaveField`，统一按"槽的最后一个真实位置"计算。
3. 每改一次就跑断言。

> 前几轮反复失败的直接原因就是跳过了第 1 步：改坏后只能靠 `git checkout` 救回。
> 曾两次把无关功能弄坏：一次是分数导航（`doLeft` 的通用 `enter(...start)`），一次是 `tools/ui_test.js` 的测试助手。

## 16.3 未实现（原始需求中的更大目标）

`LayoutBox` 引擎（`measureNode` / `layoutNode` + 绝对定位绘制）尚未实现。当前仍是 DOM + CSS `sup` 渲染。
