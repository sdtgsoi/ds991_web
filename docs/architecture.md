# 当前架构与演进方向

更新：2026-10-27。本文整理 `temp-docs/` 中适用于维护的分层思想，并以当前仓库代码为准。旧 v3 的类化 AST、Command/undo 和多层目录是设计提案，不是已经部署的结构。

## 文件与运行方式

| 文件 | 当前职责 |
|---|---|
| `ds991.html` | 页面和 CSS、键布局与统一分发、状态、表达式求值、各模式逻辑及生成区 |
| `src/math-core.js` | 可独立测试的多项式根与实数 n 次根 |
| `src/expression-editor.js` | token 编辑、模板槽、光标、导航、删除和幂输入规则 |
| `src/expression-renderer.js` | 表达式、模板、幂、光标的 HTML 排版 |
| `src/screen-renderer.js` | 各 LCD 屏幕及基于 DOM 的光标可见性 |
| `src/menus.js` | 菜单数据与导航、常数/换算、设置、复位和模式入口 |
| `tools/embed_sources.js`、`sync.sh` | 将五个源码嵌入生成区、验证脚本并同步 `index.html` |

运行时只加载 HTML，无外部 JS 依赖。直接编辑 `src/` 后必须运行 `./sync.sh`；生成区与 `index.html` 是产物。除 `math-core.js` 外，拆出的源码仍嵌入同一应用闭包，共享 `S`、`root`、`stack` 和帮助函数，不能当成已具有独立依赖接口的模块。

## 数据流与状态

```text
按钮 / 物理键盘 → dispatch(id) → 菜单、模式处理或表达式编辑
                                      ↓
                           S 状态 / root token / stack 光标
                                      ↓
                         evaluateCalculation / 模式算法
                                      ↓
                         数值、格式化 → render → LCD
```

矩阵/向量等专用编辑器和输入拦截会影响分发顺序；统一入口不等于通用状态机框架。表达式是普通对象组成的 token 数组和模板子数组，不执行用户输入的 `eval()`。光标帧的 `pos` 为数字偏移，幂结构和导航细节见 [幂编辑](power-editing.md)。

`evaluateList` 使用递归下降解析；`evaluateCalculation` 在复数模式处理有效的顶层末尾输出格式命令，再交给普通求值器。`S.complexFormat` 是全局设置，`S.resultComplexFormat` 是当前结果的临时格式；Ans 保留数值。菜单的角度/工程后缀同样要与全局设置区分。

`DS991Math` 是独立边界：多项式根接受降幂实系数并返回 `{re, im}`，支持有效次数 1–4；实数 n 次根处理负数奇次根。其余复数、矩阵、向量、统计、微积分、SOLVE 及大部分求值仍在应用闭包中。内部主要使用 JavaScript Number；分数是数值逼近，不是精确符号计算。

状态只保存在内存，刷新会丢失变量、设置、历史和模式工作数据。变量 M 与独立存储器共用 `S.M`，另有网页额外变量 Z；实体型号的状态生命周期尚未完全对齐。数值、模式与兼容性边界见 [已知限制](known-issues.md)。

## 渐进改进原则

历史 v3 建议把输入、表达式、导航、编辑、数值与渲染分层，这一职责划分仍有帮助，但不需要照搬其类层次或目录清单。优先考虑：

1. 在已有测试覆盖下逐步显式传递角度、变量、模式等求值上下文，减少隐式闭包依赖。
2. 为编辑器和渲染器建立清楚的输入、输出及 DOM 测量边界；保留 token JSON 深拷贝与数字偏移语义。
3. 按职责整理导航和删除策略，保持分数、积分、幂塔和答案后操作的回归，不以一次大改替代分步验证。
4. 讨论持久化前明确真机开关机、切模式、复位及浏览器刷新各自的语义；不直接序列化整个 `S`。
5. 精确分数/根式、布局引擎、撤销重做和大规模模块化均是独立设计问题，不能从历史提案推断已经实现。

修改源码后运行同步与适合改动的检查；DOM 模拟、真实浏览器和真机对照验证不同层，见 [测试说明](testing.md)。
