# 幂编辑与光标模型

更新：2026-10-27。本说明将 `temp-docs/` 中长期有用的指数设计、缺陷分析和验收方法与当前代码对照后整理。这里描述网页现有行为及维护约束，不代表所有细节已与 fx-991CN X 真机逐项验证。更早文档中的单停点方案、预计目录和阶段性缺陷记录是历史提案；与当前实现冲突时，以本说明、源码和测试为准。

## 表达式与光标

表达式 `root` 是 token 数组，节点是可 JSON 序列化的普通对象。幂节点有两个子数组：

```js
{t: 'pow', base: [{t: 'num', v: '2'}],
           exp: [{t: 'pow', base: [{t: 'num', v: '3'}],
                            exp: [{t: 'num', v: '4'}]}]}
```

这表示 `2^(3^4)`，并非 `(2^3)^4`。历史、CALC、SOLVE、数表等路径使用 JSON 深拷贝；改变节点表示时须保留这些路径的序列化和副本独立性，不能只检查显示。

光标 `stack` 是从根到当前槽的帧路径。帧保存 `arr`、数字偏移 `pos`，子帧还保存父节点 `node` 和槽名 `slot`。`pos` 不是数组下标：数字 token `"123"` 内有逐数字停点。`digitsIn()`、`arrDigits()`、`slotDigits()` 和偏移与 token 下标的转换帮助函数在 [expression-editor.js](../src/expression-editor.js) 中；空槽的 `slotDigits` 至少为 1。屏幕上看到的 x 坐标不足以唯一标识光标，还需检查帧路径和槽位。

幂的测量规则是 `slotDigits(base) + 1 + slotDigits(exp)`。中间偏移参与底数/指数边界映射，不能直接删去：曾尝试根据指数是否以幂开头省略该偏移，导致嵌套塔左右遍历不对称和位置回绕。

## 幂键输入决策

三种键走 `insertPower(kind)`，`kind` 为 `2`、`3` 或 `null`（一般幂）。`getPowerContext()` 为输入决定五类上下文；导航、删除和渲染也有各自的边界处理，维护时须一并核对，不能假定所有规则都已迁入独立控制器。下表的 `|` 表示光标，`□` 表示空槽。

| 上下文 | x² / x³ | x^() |
|---|---|---|
| 普通位置 | 以左侧操作数为底数 | 以左侧操作数为底数并进入空指数 |
| 顶层或指数内数字中间 | 左半升幂，右半保留：`1|23` → `1²23` | 拆分数字：`1|23` → `1^(23)`，进入指数 |
| 指数末尾 | 当前指数整体包成新幂：`2^(3|)` → `2^(3²)` | 当前指数作新底数，进入新空指数：`2^(3^□)` |
| 非空底数/指数边界 | 忽略 | 插入空底数的嵌套幂，如 `2|^4` → `2^(□^4)` |
| 顶层完整幂的外侧末尾 | 忽略 | 忽略 |

括号后的幂是普通位置：`(2^4)` 后按 x³ 可得到 `(2^4)^3`。顶层数字中间的一般幂曾错误产生空底数；当前 I10a/I10b 已锁定拆分行为。表达式中的负指数和指数内运算符也有测试。

## 导航与两侧边界

每个非空幂的底数/指数边界保留两个逻辑停点：`base@end` 和 `exp@0`。两者可能位于同一水平位置，但光标分别绘制在底数和抬升后的指数高度，输入与删除也依据所在槽不同。这是当前实现，不是旧方案中“合并为一个状态”的提议。

对于指数以另一个幂开头的情况，内层 `base@0` 与外层 `exp@0` 的第三种重复状态会折叠。`canonGapBeforePower`、`canonLeadingBaseIntoExp`、`canonDeepestExpEnd` 和 `climbOutOfNestedEnds` 负责规范化路径；`moveLeft()` / `moveRight()` 在原始移动后调用相应规范化操作。不要只按屏幕坐标判断两个停点是否重复。

`power_test.js` 对 `2^3`、`2^3^4`、`2^3^4^5` 分别验证左右遍历周期为 5、7、9，左右一致；幂塔同一文本位置不会连续出现三次。UP/DOWN 的往返路径也有单独断言。顶层首尾可以回绕；空指数槽内部按 LEFT/RIGHT 可直接穿出，而底数右端可进入空槽。答案后第一次 LEFT/RIGHT/DEL 的落点也属于回归基线。

## DEL 语义

| 位置 | 当前行为及例子 |
|---|---|
| 指数槽内非起点 | 删除光标左侧一个字符；`2^(3|)` → `2^□` |
| 指数槽起点 | 删除当前一层幂边界，将指数内容与底数合并；`123^(|45)` → `123|45` |
| 指数槽起点，内容本身是幂 | 拆除当前一层，保留更高指数；`123^(|45^67)` → `123|45^67` |
| 底数侧边界 | 删除底数末位；`12|34` 的底数侧 DEL 后为 `1^34` |
| 幂塔最深末尾或塔外末尾 | 进入最深尾槽只删除一位，不删除整个内层子树 |
| 表达式最左端 | DEL 不改变内容 |

拆除边界后光标落在**原底数右侧**，不是合并结果末尾。表达式树的结构、光标路径和保留的高层指数需要一起验证；测试中使用 `setExpr()` 可以构造删除起点，避免删除断言依赖导航本身。

## 排版与可见区域

[expression-renderer.js](../src/expression-renderer.js) 用渲染上下文传递幂层级、字体模式和根字号；`renderPow()` 将底数与 `renderExponent()` 生成的指数并排。`EXP_FONT_RATIO = 0.70`：能够测量根字号时，每一层指数均以该根字号的 70% 设定绝对像素，避免相对字号逐层缩成 70%、49%、34%。没有布局引擎时回退 `1em`，用于 DOM 模拟测试。

`EXP_STEP_EM = 0.80`：每层使用根字号的 0.80 倍作为负 `top` 偏移；相对定位在嵌套中累积，不再乘深度。`.exprline` 的普通样式为 `overflow: visible`，以免相对上移的内容被行盒裁切；另有 `.exprline.scroll` 的滚动样式，改 CSS 时需结合实际页面状态检查。

[screen-renderer.js](../src/screen-renderer.js) 的 `ensureCursorVisible()` 使用真实 DOM 测量，将表达式垂直移动并限制在 `MAX_VERTICAL_SHIFT = 60` 像素内，同时尝试水平滚动到光标。该上限避免深塔把整行推离屏幕，但不保证任意深度下整个算式或光标都可见。结果/错误状态下需检查光标隐藏规则。

## 验证与调试

```bash
./sync.sh                      # 修改 src/ 后先嵌入页面
node tools/power_test.js       # 输入、删除、导航、求值和序列化
node tools/run_tests.js        # 分数、方向键及其他模式一起回归
./tools/shot.sh /tmp/power.png "2 POW 3 POW 4 POW 5" 390 940
node tools/rects.js --keys "2 POW 3 POW 4" '.exprline' '.sup' '.cursor'
node tools/computed.js '.exprline'
```

`window.__calc` 提供 `dispatch`、`getExpr`、`getCursor`、`setExpr`、`evalExpr` 调试入口。`getExpr()` 返回当前表达式引用；需要快照时自行深拷贝。`getCursor()` 的 `path`、`slot`、`pos` 比纯文本更适合检查同屏不同槽位。`tools/render_text.js` 把 LCD HTML 归一化为文本和 `|` 光标，便于 DOM 模拟测试；它不测量浏览器布局。

`power_test.js` 的渲染项主要检查源码常量/函数，不证明像素布局。截图、计算样式和边界测量需要真实浏览器；Chrome 冒烟测试并未覆盖全部深塔、缩放、触摸或跨浏览器场景。修改边界时同时运行 `power_test.js`、`cursor_test.js`、`dpad_test.js`、`fraction_test.js` 和 `ui_test.js`，并根据改动补充最小重现的浏览器检查。

## 后续维护方向

旧 v3 方案建议显式的表达式、导航、删除、渲染和求值接口。当前只有部分源码拆分，仍共享应用闭包；没有 `PowerContext.js`、类化 AST、Command/undo、布局引擎或完整模块树。未来如需继续拆分，先固定可执行行为和 JSON 兼容，再逐块显式化依赖，避免同时更改光标模型、数值语义和渲染。旧文档中的 P1、上下移动不可逆、三重停点和深塔 DEL 整层丢失均已有回归；不要按旧“待修”状态重复实施。
